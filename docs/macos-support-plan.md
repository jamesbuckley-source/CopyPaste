# CopyPaste on macOS — plan

Status: **planned, not started.** Nothing has been implemented yet.
Written 2026-10-21 against version 0.13.6.

## Decisions taken

| Decision | Choice |
|---|---|
| Distribution format | Universal `.dmg` (arm64 + x86_64) |
| Code signing | **Ad-hoc signed for now.** Revisit a paid Apple Developer account once the port works and there is demand. |
| Tracking | Epic + one card per phase (titles listed at the end; not yet created) |

### Consequences of ad-hoc signing (accepted, not solved)

- Gatekeeper blocks the first launch. Users must right-click → Open, or run
  `xattr -dr com.apple.quarantine /Applications/CopyPaste.app`.
- In-place auto-update is fragile because the bundle's signature identity changes.
  Expect to require a manual re-download until real signing lands.
- Notarization is impossible without the account; this cannot be worked around.

## Current state of the codebase

The macOS build nearly compiles already: every `windows` crate call sits behind
`#[cfg(windows)]` with a `#[cfg(not(windows))]` stub. The stubs are *inert*, so a
Mac build launches, shows the overlay, and silently does nothing.

| Module | Behaviour on non-Windows today |
|---|---|
| `src-tauri/src/clipboard.rs` | `sequence_number()` returns `0`; all `read_*` return `None`; `write_files`/`write_file_and_text` error |
| `src-tauri/src/paste.rs` | auto-paste errors "only implemented on Windows" |
| `src-tauri/src/ocr.rs` | errors |
| `src-tauri/src/picker.rs` | screen colour picker errors |
| `src-tauri/src/sound.rs` | silent no-op |
| `src-tauri/src/window.rs` | `own_window_handle()` returns `None` |
| `src-tauri/src/crypto.rs` | legacy DPAPI unwrap fails loudly (intended) |

Already portable, no work needed: SQLite storage, search, settings, single-instance,
tray, updater plumbing, GIPHY/emoji, `arboard` (used on the image write path),
`tauri_plugin_autostart` (already initialised with `MacosLauncher::LaunchAgent`).
`src-tauri/icons/icon.icns` exists.

Known Windows-shaped defaults that need per-platform values:

- `src-tauri/src/settings.rs` — `DEFAULT_HOTKEY = "Alt+V"`, pause key `"Ctrl+Alt+P"`
- `src-tauri/tauri.conf.json` — `bundle.targets: ["nsis"]`; `decorations: false`
  yields square corners on macOS without `transparent: true`
- Frontend labels in `App.tsx`, `ClipDetailPane.tsx`, `AddClipForm.tsx`,
  `SettingsPanel.tsx`, `FirstRunWizard.tsx` ("Ctrl+Enter", "Ctrl+V", "Alt+V").
  Key *handling* is already correct — every site tests `ctrlKey || metaKey`.
- `src-tauri/src/color.rs` — path classification only recognises Windows paths.

## Phases

Estimates assume a working Mac or a `macos-14` runner to iterate against.

### Phase 0 — Make the Mac build produce a bundle (~0.5 day)

1. `tauri.conf.json`: replace the global `["nsis"]` target with per-platform
   bundles (`app` + `dmg` on macOS, `nsis` on Windows).
2. Add `bundle.macOS.minimumSystemVersion` (suggest `11.0`).
3. Verify `npm ci && npm run tauri build` on macOS. Required tooling is only
   Xcode command line tools — no Homebrew dependencies (`rusqlite` is bundled,
   TLS is rustls).
4. Confirm the `.icns` renders correctly in Finder and the Dock.

**Done when:** a `.app` and `.dmg` are produced on a Mac and the app launches.

### Phase 1 — Clipboard capture and write (~3–4 days, the bulk)

1. Restructure `clipboard.rs` from inline `cfg` blocks into
   `clipboard/windows.rs` + `clipboard/macos.rs` behind one internal interface:
   `sequence_number`, `read_text`, `read_rich_text`, `read_image`,
   `read_file_list`, `clipboard_opt_out`, `foreground_app`, `write_text`,
   `write_files`, `write_file_and_text`, `clear`.
2. macOS implementation on `objc2` / `objc2-app-kit` `NSPasteboard`:
   - `changeCount()` doubles as the sequence number; the existing 350 ms poll loop
     in `Watcher::start` works unchanged.
   - Read `public.utf8-plain-text`, `public.rtf`, `public.html`, `public.file-url`
     (multiple items), and image data (TIFF → PNG).
   - Write via `clearContents` + `setString:forType:` / `writeObjects:` with `NSURL`.
3. Privacy parity with `ExcludeClipboardContentFromMonitorProcessing`: skip captures
   carrying `org.nspasteboard.ConcealedType`, `org.nspasteboard.TransientType`, or
   `org.nspasteboard.AutoGeneratedType` (set by 1Password, Bitwarden, KeePassXC).
4. `foreground_app` becomes `NSWorkspace.sharedWorkspace.frontmostApplication`
   (bundle identifier). Normalise `ignoredApps` matching so Windows exe names keep
   working and `com.vendor.app` entries fit the same list.
5. Add POSIX/`~` path recognition to `color.rs` so Mac paths get the path tag.

**Done when:** text, images, file lists and rich text round-trip into SQLite and
back onto the pasteboard; conceal markers are respected; ignored apps work.

### Phase 2 — Window, tray, dock and hotkey (~1–2 days)

1. `set_skip_taskbar` is Windows/Linux-only. Map the "show in taskbar" setting onto
   `set_activation_policy(Accessory)` and set LSUIElement accordingly.
2. `decorations: false` yields square corners on macOS — add `transparent: true`
   and verify the existing `data-tauri-drag-region` title bar still drags. Keep the
   custom title bar for a consistent look rather than switching to native traffic
   lights.
3. Per-platform hotkey defaults (`Super+Shift+V`, `Super+Alt+P`); verify
   `CommandOrControl` parsing in `hotkey.rs`.
4. Tray: menu-bar extra with a template icon so it inverts in dark mode.
5. Confirm Cmd+Q, Cmd+W and webview copy/paste work via the default macOS app menu.
6. Overlay behaviour across Spaces and full-screen apps (`visible_on_all_workspaces`,
   floating window level).

**Done when:** hotkey summon, tray menu, close-to-tray, always-on-top, autostart and
quit all behave on a Mac.

### Phase 3 — Windows-only features (~2–3 days)

1. **Auto-paste** (`paste.rs`): capture the frontmost `NSRunningApplication`,
   reactivate with `activateWithOptions`, synthesise ⌘V via `CGEventPost`. Requires
   the Accessibility TCC grant — detect with `AXIsProcessTrustedWithOptions`, fail
   with a message pointing at System Settings, and explain it in the first-run wizard.
2. **OCR** (`ocr.rs`): Vision `VNRecognizeTextRequest`. Offline, no permission needed.
3. **Screen colour picker** (`picker.rs`): `CGDisplayCreateImage` + cursor position.
   Requires Screen Recording permission on 10.15+. Build the magnifier overlay with
   Tauri rather than a Win32 window class.
4. **Sounds** (`sound.rs`): `NSSound` for the existing bundled WAVs.
5. Legacy DPAPI migration stays Windows-only; document it.

**Done when:** each feature either works or degrades with an explanatory message, and
no path panics.

### Phase 4 — Platform-aware shortcut labels (~0.5 day)

1. Add a platform helper (a `platform()` command or `@tauri-apps/plugin-os`).
2. Replace hard-coded "Ctrl+Enter", "Ctrl+V", "Alt+V" strings with ⌘⏎ / ⌘V / ⌘⇧V on
   macOS. Key handling itself needs no change.

**Done when:** no Windows-only key names appear in the Mac UI.

### Phase 5 — Universal `.dmg` and release pipeline (~1 day)

1. Universal build: `rustup target add aarch64-apple-darwin x86_64-apple-darwin`,
   build with `--target universal-apple-darwin`. This roughly doubles compile time;
   consider arm64-only first if release cadence matters more.
2. `release.yml` becomes a matrix (`windows-latest`, `macos-14`), keeping
   `cargo test` gating both.
3. **`latest.json` conflict:** each job writes its own `latest.json` and the Windows
   job currently publishes it alone. Add a merge step that combines the `platforms`
   map from both jobs before upload, or Mac clients receive a Windows-only manifest.
4. Ad-hoc signing: `codesign -s -` in CI, plus README instructions for bypassing
   Gatekeeper on first launch.
5. Stable asset alias alongside the existing `CopyPaste_x64-setup.exe`, e.g.
   `CopyPaste_universal.dmg`.
6. Leave a `TODO` in the workflow for Developer ID secrets (`APPLE_CERTIFICATE`,
   `APPLE_SIGNING_IDENTITY`, `APPLE_ID`, `APPLE_PASSWORD`, `APPLE_TEAM_ID`) so
   signing can be switched on later without redesigning the job.

**Done when:** tagging `v*` publishes a Windows installer and a Mac `.dmg` from the
same release.

### Phase 6 — Docs and QA (~1 day)

1. README: platform table, Xcode CLT prerequisites, the Accessibility and Screen
   Recording permissions, per-feature Mac status table, Gatekeeper first-launch note.
2. Manual QA matrix on real hardware: text/image/file capture, conceal markers,
   hotkey, auto-paste, OCR, colour picker, sounds, tray, autostart, data-dir move,
   Markdown export, GIPHY search, updater round-trip.

**Done when:** a Mac user can follow the README from download to working app.

## Risks

1. **Cannot be verified from Windows.** Phases 1–3 need a Mac or a `macos-14` runner.
   Expect several rounds of AppKit/TCC surprises. Land Phase 0 and a skeleton Phase 1
   early so CI starts building the target.
2. **TCC permissions cannot be automated.** The Accessibility and Screen Recording
   prompts are user grants; the first-run wizard must explain them.
3. **Auto-paste and the colour picker** are the two features most likely to stay
   degraded on Mac if the permission friction proves unacceptable to users.
4. **Updater on an ad-hoc signed bundle.** Replacement semantics are undefined when
   the signing identity changes; until Developer ID signing lands, treat the updater
   as Windows-only in practice.
5. **Universal builds** double compile time and complicate debugging; arm64-only is a
   legitimate phase-one shortcut.

**Rough total: 9–12 focused days**, realistically 2–3 weeks including hardware
iteration.
